# @angular-community/qwik-cdk/a11y

Qwik port of [@angular/cdk/a11y](https://github.com/angular/components/tree/main/src/cdk/a11y) (focused subset for Dialog).
Exports `_IdGenerator` (stable cross-SSR IDs), `InteractivityChecker`, `InputModalityDetector`, `FocusMonitor`, `FocusTrap`, and the `useFocusTrap` / `useFocusOrigin` hooks with their context IDs and `use*` helpers. `useFocusOrigin()` is the lazy (`useOn()`-based, no per-instance `useVisibleTask$`) hook consumed by `qwik-material/button-toggle`, `qwik-material/button`, and `qwik-material/expansion`. `focusVia(element, origin, options)` (2026-10-27, for expansion) is a lazy, attribute-based companion: it forces the ORIGIN `useFocusOrigin()` attributes to the very next focus event on `element`, for callers that need upstream `FocusMonitor.focusVia()`'s exact-origin semantics (`MatAccordion`'s arrow-key navigation, `MatExpansionPanelHeader`'s focus-return-on-close) without the heavier engine below. `FocusMonitor`/`createFocusMonitor`/`FOCUS_MONITOR` remain exported as the faithful low-level CDK port (its own, heavier `focusVia()`, or a shared engine wired up manually) — see SYNC.md for why the old `useFocusMonitor()` convenience hook was removed in favor of `useFocusOrigin()`, and for why `focusVia()` above was built as a `useFocusOrigin()` companion instead of reaching for this engine.
`LiveAnnouncer` (`createLiveAnnouncer()`, added 2026-10-28 for `qwik-material/snack-bar`'s `announcementMessage` support — the live element is created lazily on first `announce()`, not eagerly) is also exported. The `cdkAriaLive` directive, `cdkTrapFocus` directive, and `FocusKeyManager`/`ActiveDescendantKeyManager` are deferred. See SYNC.md for porting deviations.
